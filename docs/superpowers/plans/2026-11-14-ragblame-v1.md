# ragblame v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Python CLI that runs a local Docker-docs RAG bot. For each wrong answer it names the stage that caused it, by re-running the question with that one stage made perfect, and it can also simulate fixes and prove its own accuracy on injected faults.

**Architecture:**
- `DemoBot` is a swappable-stage RAG pipeline: chunker → embedder → FAISS index → cross-encoder reranker → packer → MLX generator.
- Its primitives (`search`, `rerank`, `pack`, `answer`, `rechunk`) form the `Pipeline` protocol.
- `diagnose` composes those primitives with stage-local "perfect" swaps.
- Claude, through `claude -p` with a disk cache, writes questions, judges answers, explains verdicts and serves as the baseline trace-reader.
- Every run writes `runs/<id>/results.json`, which the HTML report renders.

- numpy, faiss-cpu
- sentence-transformers and torch, on MPS
- mlx-lm ≥0.32

## Review Focus

1. **The gold quote appears in more than one place,** for example the same table on two pages. Every chunk containing the span counts as gold, and loss-point uses the best-ranked one. Test in Task 3.
2. **Claude's quote isn't verbatim,** for example because of markdown pipes, extra whitespace or smart quotes. Matching is whitespace- and quote-normalised, an unmatched quote is rejected and counted, and the run doesn't crash. Test in Task 6.
3. **A `claude -p` call fails:** non-JSON reply, non-zero exit, timeout or rate limit. Retry 3 times with backoff, never cache a failure, and mark that question `error` rather than aborting the run. Test in Task 6.
4. **Generator output has `<think>` blocks or runs on.** Strip think blocks, cap max_tokens, and strip trailing whitespace. Test in Task 5.
5. **The first packed chunk is bigger than the budget.** Truncate that chunk to the budget rather than packing nothing. Test in Task 5.

## Shared types (`ragblame/types.py`, Task 2; everything else consumes these)

```python
@dataclass(frozen=True)
class Doc:      id: str; title: str; url: str; text: str
@dataclass(frozen=True)
class Chunk:    id: str; doc_id: str; start: int; end: int; text: str   # id = f"{doc_id}#{n}", text == doc.text[start:end]
@dataclass(frozen=True)
class Hit:      chunk: Chunk; score: float
@dataclass(frozen=True)
class Gold:     doc_id: str; start: int; end: int; quote: str
@dataclass
class Question: id: str; text: str; answer: str; gold: Gold | None
@dataclass
class Judgement: label: str; reason: str
@dataclass
class Trace:    question_id: str; exact: list[Hit]; candidates: list[Hit]; reranked: list[Hit]; packed: list[Chunk]; prompt: str; answer: str
@dataclass
class Experiment: swap: str; description: str; answer: str; judgement: Judgement
@dataclass
class Verdict:  cause: str; stages: list[str]; loss_point: str | None; experiments: list[Experiment]; explanation: str; fix: str
```

All of these serialise with `dataclasses.asdict`. `Trace.exact` holds the top 50 hits from exact search with the bot's embedder; that's instrumentation and isn't used for answering.

### Task 8: Diagnosis engine

**Files:**
- Create: `ragblame/diagnose.py`, `tests/test_diagnose.py`
- Modify: `ragblame/cli.py`, so `run` diagnoses by default

**Interfaces:**
- Consumes: `Pipeline`, `Trace`, `Question`, `judge`, `gold_chunks`, `is_intact`.
- Produces:
  - `loss_point(trace, gold_ids, intact, k_candidates, top_n) -> str | None` returns, in order:
    1. `chunking` if not intact;
    2. else `embedding` if no gold id is in `exact[:k_candidates]`;
    3. else `index` if none is in `candidates`;
    4. else `ranking` if none is in `reranked[:top_n]`;
    5. else `packing` if none is packed or the first gold isn't at packed position 0;
    6. else `None`.
  - `SWAPS` maps each stage to its perfect swap. Each swap is stage-local: it keeps upstream outputs and recomputes downstream with the pipeline's own primitives.
    - `chunking`: `pipeline.rechunk(gold)`, then a full re-run.
    - `embedding`: candidates = gold chunks + ANN candidates, deduplicated and cut to k.
    - `index`: candidates = exact search top-k.
    - `ranking`: gold chunks moved first among the candidates.
    - `packing`: the gold chunk packed first, then the others within budget.
    - The oracle swap answers with only the gold quote as a chunk.
  - `diagnose(pipeline, question, trace, *, judge_fn) -> Verdict` follows spec §5:
    1. no gold → `docs_gap`;
    2. oracle fails → `generation`;
    3. if the loss-point swap alone gives `correct`, blame that stage;
    4. otherwise add downstream swaps cumulatively, and on the first `correct` the verdict is `multiple`, with those stages;
    5. if the loss point is None and the gold is packed first → `distracted`;
    6. otherwise `unresolved`.

    Every swap tried is recorded as an `Experiment`. A pipeline without `rechunk` records "skipped: pipeline has no rechunk hook".
  - `explain(question, trace, verdict) -> tuple[str, str]` uses Claude to write a plain-English explanation and a fix. The fix is drawn from the named fixes in Task 10, mapped by cause.
  - **Deviation from spec §5:** the swap order comes from the deterministic loss point, not from Claude, because that's cheaper, testable and reproducible. Claude's role in diagnosis is the explanation and the fix, plus the gold-finding and judging around it. If the user objects, the spec wins.
